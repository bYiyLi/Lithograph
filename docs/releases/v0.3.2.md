# Lithograph v0.3.2

v0.3.2 新增 query-local 查询、返回与写入访问控制，修复 canonical 状态重组、字符串插值与作用域，以及 OpenAI-compatible Provider cache 的首次并发初始化。保持 `CY25-2026.08`、storage format **3** 与 `EmbeddingProviderV1`。

## 查询、返回和写入访问控制

应用继续通过 `lithograph(query, params, options)` 与 `lithograph_rows(query, params, options)` 调用，在第三个参数中加入 `readAccess` / `writeAccess`。省略配置、空对象或未填写的 Boolean 不额外限制现有能力；明确规则和显式 false 才收紧权限。

- `readAccess.query` 将受限 Node/Relationship 属性按不存在处理，覆盖静态/动态访问、条件、计算、聚合、枚举、子查询与路径。依赖隐藏字段的 Search、需要完整暴露受限属性的版本资料返回权限错误。
- `readAccess.result` 在公开 JSON 编码时递归过滤 Node、Relationship、Path 及 List/Map 内的图对象；显式 scalar、`properties(n)`、`n{.*}` 和普通 Map 保持查询结果。需要禁止真实取值时，同时配置 query。
- `writeAccess` 保护属性的新增、更新和移除，覆盖动态 key、null 删除、Map 合并/替换、隐含删除与显式写回相同值；另外可以分别限制创建、删除、Label、Schema、版本与维护。
- 属性规则支持精确名、字面前缀与完整名称 regex；读取侧可以禁止规范函数、命名 Procedure、SHOW、EXPLAIN、PROFILE 与外部 I/O。所有规则与旧只读、Snapshot、Graph View 和事务边界取交集。
- Patch、Reset、Revert、Merge、Rebase、Squash 按最终有效图/Schema 变化检查；Merge finalize 使用本次调用的权限重验。历史重组内部 replay 不等于新增的业务写入。
- 新错误 `ACCESS_DENIED` 对应 SQLite `SQLITE_AUTH` (23)；配置错误仍为 `INVALID_ARGUMENT`。scalar、rows、显式事务及独立/并发批次共享策略，既有 rollback、ON ERROR 与 earlier durable batch 语义保持。

调用流程见 [访问控制指南](https://github.com/bYiyLi/Lithograph/blob/v0.3.2/docs/guide/access-controls.md)，准确字段与默认值见 [Execution Options](https://github.com/bYiyLi/Lithograph/blob/v0.3.2/docs/reference/execution-options.md#access-controls)，失败范围见 [事务参考](https://github.com/bYiyLi/Lithograph/blob/v0.3.2/docs/reference/transactions.md#access-controls)。v0.3.1 不接受这两个新增 key。

## Canonical 状态修复

- Squash 的完整属性状态保留正负零，避免将 `-0.0` 重组为 `+0.0`；覆盖 Scalar、List、Point 与浮点 Vector 等属性。
- 无关字段的 Revert/Patch 不再因未改变的 canonical NaN 错误报告 before-condition 冲突；Diff、Patch applicability、Merge candidate/resolution、Rebase 与 virtual base 使用同一 canonical logical-slot 状态。
- Schema/Index 的 opaque providerConfig 保留标量与嵌套数值的 canonical identity，避免正负零定义变化被折叠、错误接受 Patch before 或绕过 Schema 权限；受限 Merge finalize 失败保留 Session、revision 与 Branch。

这些修复遵守既有 storage/version 合同。Cypher 查询中的数值相等规则不变，不重写既有 Commit ID，也不改变存储格式。

## 插值、作用域与查询边界修复

修复 reduce 的规范函数名识别，以及字符串插值内 COUNT/COLLECT/EXISTS 的真实图查询求值与策略传播。短路求值保留 lazy branch 与三值逻辑；列表作用域、累加器、变量遮蔽和投影排序保留正确的行/分组上下文，受限图属性与普通 Map 继续遵守各自含义。

插值中的命名 Procedure 继续受外联、维护、版本组合、Merge candidate 上下文及显式事务生命周期限制，避免表达式包装绕过既有执行边界。

## Provider cache 首次并发初始化修复

修复多个进程首次同时初始化同一空 cache 时可能返回 `IO_ERROR` 的竞争。初始化取得 SQLite writer 后重新核对状态，验证并使用其它进程已经完成的合法 Schema；严格识别 Provider 自有 table，拒绝用户 VIEW/index/trigger 或 `sqlitex` 对象被当作空 cache 接管。

missing path 与已有空文件的多进程回归验证 winner 发布后 stale reader 全部成功，向量、UNIQUE/accounting、既有 entry 与离线 reopen/hit 正确。初始化取消或锁等待超时不留下 partial Schema，解除阻塞后可恢复；foreign Schema 与外部对象拒绝保持零 HTTP/无修改。合法 in-budget warm hit 不额外要求 writer。

cache schema/key version、配置字段、Provider SPI 与 graph storage 不变。v0.3.1 的历史问题和串行预热规避继续适用于该版本，见 [Known Issues](https://github.com/bYiyLi/Lithograph/blob/v0.3.2/docs/reference/known-issues.md#provider-cache-first-use)。

## 兼容、升级与运行要求

- 保持标准 SQLite loadable extension 与 SQL-only application execution；不新增 Server、账号系统、application query ABI 或 Rust 源码桥。
- `CY25-2026.08`、storage format **3**、既有 Commit identity 与 `EmbeddingProviderV1` 保持不变。新执行选项不增加 Cypher grammar coverage 分母。
- 读取 formats 1–3，新建/迁移目标为 3。从 v0.3.1 升级不要求新的存储迁移；历史 v0.2.0/v0.2.1 的 format 4 不支持直接降级/迁移，不能手改 marker。
- 运行要求为 SQLite 3.45.0+、loadable extension、FTS5 与线程安全支持。Provider-owned cache 是独立文件，不纳入图的 Commit、备份或回滚边界。
- Procedure 参数/返回 metadata 与 `SHOW INDEXES.createStatement` 完整性限制仍保留，按手写 Reference 使用实际类型/definition。

# Lithograph v0.2.0

Lithograph v0.2.0 发布 Phase 13 的 Managed Semantic Vector / Embedding Provider 能力。Raw Vector Property、Vector Index 与 Cypher 25 `SEARCH` 保持不变；Managed Semantic 作为并列的 Lithograph procedure extension，把 String Property 通过 connection-local Embedding Provider 转换为 derived FLOAT32 Vector。

Native ABI 仍为 1，Cypher profile 仍为 `CY25-2026.08`。storage format 从 3 提升为 4。

## Managed Semantic

- Node / Relationship Semantic Index 使用一个 exact String source Property、Provider、versioned `providerConfig`、dimensions 与 similarity 定义 embedding space。
- `db.index.semantic.queryNodes` / `queryRelationships` 执行文本相似度查询；Graph View 在 Provider input 与 top-k 前生效，历史查询使用目标 Commit 的历史 IndexDefinition。
- 普通 semantic query 会自动填充 persistent Embedding Result Cache；query/source exact text 在相同 embedding space 下可跨 connection/process restart复用，不需要先执行 rebuild或预热。
- `db.index.semantic.rebuild` 保留为可选维护能力；`cache.configure/stats/clear` 管理 database-local derived cache。普通 query publish与这些维护操作都不创建 graph Commit、不移动 Branch。
- Diff/Patch/Merge/Rebase/Revert 发布新增或修改 Semantic definition 前重新验证目标 Provider；失败不会移动 Branch。

## OpenAI-compatible Provider

每个平台发布包同时包含 Lithograph 主 extension 与独立的 `lithograph-openai-compatible` SQLite extension。实际执行 Semantic create/query/rebuild 的每个 SQLite connection 都需要加载相应 Provider。

OpenAI-compatible Provider 支持 versioned endpoint、model、auth/header、dimensions、encoding、timeout、retry 与 batch 配置。它固定调用 `<base_url>/embeddings`，不自动跟随 3xx redirect，也不自动读取 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`。需要兼容网关或代理时，应把最终可访问 endpoint 明确写入 `base_url`。

直接写入 `providerConfig.api_key` 或 secret custom header 会按原值进入 Schema history、SHOW、Diff/Patch 与 backup。若不希望把 credential 写入数据库，使用 `api_key_env`，数据库只保存环境变量名。

## 从 v0.1.1 升级

1. 停止写入并保留完整数据库备份，记录当前 extension 版本与 storage format。
2. 在一次性副本或维护窗口中加载 v0.2.0，并调用 `lithograph_init()` 执行 format 3 → 4 migration。
3. 运行 `lithograph_integrity()`，再在真实宿主 runtime 中执行代表性读写、Full-text、Raw Vector 与 Semantic smoke。
4. 确认应用的每个 Semantic connection 都加载所需 Provider 后再恢复流量。

迁移只创建空的 derived embedding-cache inventory/config，不扫描 graph、不调用 Provider，也不改变既有 Commit/Layer/Schema identity。加载 extension 与普通查询不会自动迁移；只有显式 `lithograph_init()` 才会更新 storage format。format 4 没有自动 downgrade，回退应恢复升级前备份，而不是让 v0.1.1 binary 继续写 format 4 文件。

v0.1.1 的 Full-text tokenizer specification 行为保持不变；从 v0.1.0 跨版本升级时仍需阅读 [v0.1.1 Release Notes](v0.1.1.md)。

## Runtime 与兼容性

- 最低 SQLite：3.45.0，必须支持 loadable extension 与 FTS5。
- Release gate 同时验证 SQLite 3.53.4。
- Native ABI：1，未改变。
- Embedding Provider ABI：V1，connection-local。
- Cypher profile：`CY25-2026.08`，未改变。
- storage format：读取 1–4，新建与迁移目标为 4。
- Raw Vector / `SEARCH`、Full-text、Version operations 与 v0.1.1 的既有合同保持不变。

## 已知边界

- Managed Semantic v1 不提供自动 chunk/truncate、multi-source concat、Reranker、通用 AI plugin framework 或 vendor-specific Azure/Ollama API。
- Semantic query/rebuild 即使 persistent cache 已 warm，仍要求目标 Provider 当前已加载并通过 validation。
- Provider/network 行为属于 external I/O；不能与 graph mutation、Native explicit transaction 或 `lithograph_rows()` 混用。
- `lithograph.branch.checkout` 的既有 adapter transaction-boundary 问题、Native `NULL,0` JSON 默认值问题与 Procedure introspection 类型 metadata 限制仍保留；使用 [Known Issues](../reference/known-issues.md) 中的规避路径。
- 本版本仍是 pre-1.0 release；升级生产数据库前必须使用真实宿主 SQLite、连接池、凭据注入与网络路径完成 smoke 和恢复演练。

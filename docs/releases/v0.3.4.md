# Lithograph v0.3.4

v0.3.4 增加 Graph View 的**多 Label 并集筛选**，并修复两项 TLS 证书验证依赖的安全公告。保持标准 SQLite loadable extension、`CY25-2026.08`、storage format **3**、immutable Commit 历史及 `EmbeddingProviderV1` 合同不变。

## Graph View：`requireAnyLabels`

`lithograph(query, params, options)` 与 `lithograph_rows(query, params, options)` 的第三个 JSON 参数支持：

```json
{
  "graphView": {
    "requireAllLabels": ["Scope"],
    "requireAnyLabels": ["Article", "Note"],
    "excludeAnyLabels": ["Internal"]
  }
}
```

在同一个 Snapshot 中，Node 必须满足三个条件：同时拥有全部 `Scope` 类必需 Label（AND）；拥有 `Article` **或** `Note` 中至少一个（OR）；并且不拥有 `Internal` 等任意排除 Label（NOT）。这不是把两次查询取回后合并，也不是给 Cypher 增加新的查询语法。

- 三个数组都可省略或置空，原有调用默认保持完整图语义。内部重复 Label 按精确名称去重；同属多个 OR Label 的 Node 在一次 NodeScan 中只出现一次。
- `requireAnyLabels` 与排除条件可以重叠，排除优先；`requireAllLabels` 与 `excludeAnyLabels` 交集仍为 `INVALID_ARGUMENT`。未知 Label 不创建字典 entry；全部 OR 候选都不存在或被排除时结果为空。
- Relationship 仅在两个端点都可见时可见。普通 MATCH、OPTIONAL、聚合、子查询、路径、索引查找和 `EXPLAIN`/`PROFILE` 都使用同一可见子图。
- Full-text、Raw Vector `SEARCH` 和 Managed Semantic 的候选在 Top-K、skip/limit 之前应用 View。受限 Provider 输入和 HNSW/TEMP 缓存不能跨不兼容的 View 或历史 Snapshot 泄漏。
- 普通写入及历史只读继续遵循 clause 边界：新 Label 可以通过合法 CREATE/MERGE 在后续 clause 可见；导致修改后元素离开 View 或越界删除的操作返回 `GRAPH_VIEW_VIOLATION` 并回滚。

例：在同一 SQLite connection 执行（以已创建的 Label 为准）：

```sql
SELECT lithograph(
  'MATCH (n) RETURN n ORDER BY elementId(n)',
  '{}',
  '{"graphView":{"requireAnyLabels":["Article","Note"]}}'
);
```

完整示例、错误及组合规则见 [Graph View 指南](../guide/graph-views.md) 和 [Execution Options](../reference/execution-options.md#graph-view)。

## 兼容、安全与升级

- `requireAnyLabels` 从 **v0.3.4** 提供。v0.3.3 及更早发行版不认识该字段，传入会返回 `INVALID_ARGUMENT`；`requireAllLabels`、`excludeAnyLabels` 和缺省行为不变。
- Graph View 是宿主选择的 query-local 范围，**不是租户权限或认证机制**。能够自行传 SQL/options 的调用方仍能省略 View；必须由可信宿主强制构造并校验范围。
- Schema、Constraint、Index 定义和 Version Procedure 仍不属于 Graph View；非空 View 不允许与这些操作组合。Graph View 不修改 Commit ID、持久化数据或 Schema，也不要求额外数据库迁移。
- 存储继续支持格式 1–3，fresh/current format 为 **3**。历史 format 4 的迁移限制不变；SQLite 需 **3.45.0+**、loadable extension、FTS5 和线程安全。
- `Cargo.lock` 将 `rustls-webpki` 升级至 `0.103.16`、`webpki-roots` 升级至 `1.0.10`，修复证书链相关的 RUSTSEC-2026-0382 / RUSTSEC-2026-0381。没有新增应用 API、配置项或 Provider SPI 版本。

## 代码与验收

[Phase 20](../development/phases/20-graph-view-label-union.md) 的本机源码验收通过：新增 Core **11/11**，完整 `cargo make quality` 与 `scripts/ci.sh` 均 exit 0，适用 TCK **3,777/3,777**，覆盖 SQLite 3.45.0 / 3.51.0 / 3.53.4 的真实扩展加载、SQL scalar/rows、事务、Full-text/Vector 和 synthetic Embedding Provider。上述验收是开发基线证据，不代替 Tag 自身的远端 CI、六平台资产和下载后验证。

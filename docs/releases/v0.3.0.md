# Lithograph v0.3.0

Lithograph v0.3.0 发布 Phase 15：application-facing query execution 收敛为 SQLite SQL-only，`lithograph_rows()` 升级为真正的统一 execution event stream，SQL explicit transaction 直接复用普通 execution surface，Managed Semantic 的 persistent text → Vector result cache 改由具体 Embedding Provider 自己拥有。

这是一个 **breaking pre-1.0 release**。v0.2.0/v0.2.1 的 application-facing Native query ABI、`lithograph_tx_execute()` 与 Lithograph-owned embedding cache 已删除；fresh/current Lithograph storage format 为 3。

## SQL-only Application Execution

应用只需要通过自己的 SQLite driver 加载 Lithograph extension，并使用 SQL：

- `lithograph(query [, params_json [, options_json]])`：完整消费 execution，返回单个 JSON envelope；
- `lithograph_rows(query [, params_json [, options_json]])`：返回 `ordinal/event/data` 三列的 execution stream，事件顺序为 `columns -> row* -> summary`；
- `lithograph_tx_begin(options_json)`、普通 `lithograph()` / `lithograph_rows()`、`lithograph_tx_commit()` / `lithograph_tx_abort()`：组成 connection-scoped explicit transaction。

`lithograph_rows()` 不再是 read-only adapter。mutation、`LOAD CSV`、Managed Semantic 与 `CALL { ... } IN TRANSACTIONS` 都可以通过同一 stream 执行；未到 success `summary` 就关闭的普通 side-effecting execution 会回滚尚未发布的当前 execution。

Application-facing `lithograph_v1_*` query/transaction C ABI 与 `include/lithograph.h` 不再属于产品 surface。C/C++ host 与其它语言一样使用标准 SQLite API；独立 `EmbeddingProviderV1` SPI 继续保留。

## True Streaming

Phase 15 重构 query execution，使 read、mutating `RETURN`、transaction subquery 与 `LOAD CSV` 可以按 pull/backpressure 方式推进，而不是由 adapter 先物化全部最终结果：

- 大结果通过 bounded batches / TEMP spill 控制额外内存；
- mutating stream 在 publication 前的 encoding、interrupt、early-close 等失败会 rollback；
- `IN TRANSACTIONS` 只在每个 batch 真正 commit 后公开该 batch 的成功 rows；
- 慢 consumer 不触发后台无界执行，early-close 会停止尚未开始的后续工作；
- outer SQL `WHERE` / `LIMIT` 只决定 stream 的消费方式，不重新定义 Cypher execution 语义。

## Explicit Transaction

v0.3.0 删除 v0.2.1 的独立 `lithograph_tx_execute()`。新的正常用法是：

```sql
SELECT lithograph_tx_begin('{"author":"app","message":"create two people"}');
SELECT lithograph('CREATE (:Person {name: ''张三''}) FINISH');
SELECT lithograph('CREATE (:Person {name: ''李四''}) FINISH');
SELECT lithograph_tx_commit();
```

同一 explicit transaction 内的普通 `lithograph()` / `lithograph_rows()` 可见 staged state，并在最终 commit 时形成一个 graph Commit。execution failure、stream summary 前 close 或 cancel 会按合同 fail-closed abort 整个 active explicit transaction。

## Managed Semantic 与 Provider-owned Cache

Lithograph Core 不再持有 persistent embedding cache，也不创建 `_lithograph_embedding_cache` 或相关 metadata。

OpenAI-compatible Provider 新增可选 `providerConfig.cache`：启用后使用一个与 Lithograph main database 独立的 SQLite 文件持久化 Provider result cache。cache identity 只包含 request semantic identity；credential、raw input text 与 secret header 不写入 cache key、数据库、日志或错误信息。cache corruption、budget、并发 BUSY/LOCKED、取消与 same-main-path rejection 都有明确 fail-closed 行为。

## Storage 与升级边界

v0.3.0 支持 Lithograph storage format 1–3，fresh/current format 为 **3**；format 1/2 可通过 `lithograph_init()` 迁移到 3。

历史 v0.2.0/v0.2.1 release 使用 format 4。v0.3.0 **不提供 format 4 → 3 downgrade/migration**，也不会把旧 format 4 database 静默解释为 format 3。需要继续使用旧 database 时保留对应 v0.2.x binary/tag；需要切换到 v0.3.0 时应通过应用自己的数据导出/重建流程建立新的 format 3 database。

## Runtime 与兼容性

- 最低 SQLite：3.45.0，必须支持 loadable extension 与 FTS5。
- Release gate 同时验证 current/frozen SQLite runtime。
- Application-facing Native query ABI：无；使用标准 SQLite SQL surface。
- Embedding Provider ABI：V1。
- Cypher profile：`CY25-2026.08`。
- storage format：读取 1–3，新建与迁移目标为 3。

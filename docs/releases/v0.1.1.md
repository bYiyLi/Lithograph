# Lithograph v0.1.1

Lithograph v0.1.1 发布 Phase 12 的 Full-text / FTS5 Tokenizer 扩展能力。Native ABI 仍为 1，Cypher profile 仍为 `CY25-2026.08`，storage format 仍为 3；本版本不引入 storage migration。

## Full-text Tokenizer

- `fulltext.analyzer` 直接使用完整 SQLite FTS5 tokenizer specification，默认 `unicode61`。
- FTS5 自带 tokenizer 与参数可以原样组合，例如 `porter unicode61`、`unicode61 remove_diacritics 0 tokenchars '-_'`。
- Full-text DDL 在发布 Schema / IndexDefinition 前，会在当前宿主 SQLite connection 上调用真实 FTS5 constructor 验证 specification。
- 第三方 tokenizer 由宿主 SQLite extension 注册；Lithograph 只保存 specification 字符串，不内置第三方 tokenizer，也不把 native 实现写入数据库。每个实际使用相关 Index 的 connection 都需要完成对应注册。
- query-time `analyzer` override 使用相同 specification，并委托原生 FTS5 QUERY/PREFIX tokenizer；短语、布尔、prefix、Property 限定与 colocated synonym 继续由 FTS5 MATCH 语义处理。
- 历史查询与 derived cache 按所选 Snapshot / IndexDefinition 使用对应 specification；历史 definition 不会被当前 Branch 的配置覆盖。

## 从 v0.1.0 升级

这是一个明确的 **Full-text 配置行为变化**：

- v0.1.0 的 `standard-no-stop-words` / `english` 特殊映射已移除。v0.1.1 会把 analyzer 值按 FTS5 tokenizer specification 解释，不再把这些名称改写为 Lithograph 内置实现。
- 已有历史 definition 不会被原地重写。若现有 definition 保存了旧名称，而宿主没有注册同名 FTS5 tokenizer，v0.1.1 在需要构造该 tokenizer 的 DDL、查询或冷重建路径上会失败，而不是静默 fallback。
- 需要 stemming 时显式使用适合应用语义的 FTS5 specification，例如 `porter unicode61`；它不是 Neo4j `english` analyzer 的自动等价替代。
- 升级已有 database 前继续保留完整备份。storage format 仍为 3，无自动 downgrade。

## Runtime 与兼容性

- 最低 SQLite：3.45.0，必须支持 loadable extension 与 FTS5。
- Release gate 同时验证 SQLite 3.53.4。
- Native ABI：1，未改变。
- Cypher profile：`CY25-2026.08`，未改变。
- storage format：3，未改变。
- Full-text tokenizer provider 是 SQLite connection-local 能力；第三方 tokenizer 的部署、加载顺序与连接池注册由宿主应用负责。

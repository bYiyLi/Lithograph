## 13:48 — Native explicit transaction design synchronization

Scope and authorization: 用户要求整理优化 Lithograph 的设计文档与开发计划，修复此前已确认但未同步进 Lithograph 真源的“多个独立 Cypher execution -> 一个 Commit”能力；仅修改设计/开发文档与本日志，不实现代码、不提交、不推送，并保留当前工作树中既有 Phase 07 代码修改。

### Decisions

- `docs/design.md` 正式冻结 Native explicit transaction 的产品语义：`begin -> execute* -> commit | abort`，多个标准 Cypher current-graph execution 共享 staged graph/Schema/Index state，成功时只有一个最终 Commit；该能力提供 version atomicity，不等同于 caller-owned SQLite transaction 的 durability atomicity，也不改变 Cypher `IN TRANSACTIONS` 的 per-batch Commit 语义。
- transaction begin 可带 `expectedHead=commit/<id>`，在 single-writer ownership 下原子校验；transaction 内 statement 继续使用普通 immediate Cypher Schema/Constraint/Graph View semantics，不引入 deferred constraints；任一 execution/callback/cancel/commit failure fail-closed abort。
- Phase 09 是 transaction -> Commit completion owner；Phase 05 保留单-query auto-commit foundation，Phase 08 保留 Cypher transaction batching。Phase 10 增加 crash、scale、跨平台和 release regression closure。
- Native ABI 采用 additive `_v1_` explicit-transaction family 与 opaque handle；本次冻结生命周期、logical options/result/error semantics，准确 C handle 参数/ownership layout 由 Phase 09 在不修改既有 v1 symbols 的前提下编码并回写 Design。

### Changes

- 更新 `docs/design.md`：产品定义、versioning driver、Native ABI/transaction options、temporal clock、Transaction/Concurrency Model、result contract 与新增 D10 architecture decision。
- 更新 `docs/development/README.md`、`architecture-roadmap.md`：明确 Phase 09 completion ownership、vertical slice、全局 Storage/Version 与最终产品 acceptance。
- 更新 Phase 08：明确 `IN TRANSACTIONS` 不等于 multi-execution single-Commit。

# Lithograph v0.3.5

v0.3.5 交付 **Phase 21：MATCH 谓词安全下推与版本化 Node Element ID Seek**，重点减少多 Pattern 查询中过晚过滤导致的无效候选扩展，以及精确身份查询的全图扫描。继承 v0.3.4 的 Graph View `requireAnyLabels`，不修改 application-facing SQL、Cypher 25 Profile、存储格式和版本历史模型。

## 查询优化

- Read 与 Write MATCH 对可证明安全的确定性单变量 AND 前缀，在进入后续 Pattern Part 前进行提前过滤。保留原始 WHERE 与 residual，确保跨 Part、OR、OPTIONAL、NULL、异常时序、重复绑定、子查询及写入边界的正确性。
- `elementId(n) = $id` 和 `$id = elementId(n)` 可使用真正的版本化 Snapshot `NodeIdSeek`。对 Label、Graph View、访问控制、历史 Commit 和 explicit transaction 的 staged CREATE/DELETE 继续验证；非法类型和缺失节点沿用既有语义。不声称 `IN` 成员 Seek 已实现。
- `EXPLAIN` / `PROFILE` 反映实际提前过滤和 Seek 算子工作量，不通过仅改展示字符串模拟性能改进。Read/Write 共用执行路径；复用流式、取消、预算和事务回滚。

## 本地性能和正确性验收

- 80 Node 的受控双 Pattern 复现：旧版计划 `LabelIndexScan → Cartesian → LabelIndexScan → Filter` 的 PROFILE 为 `12,960 dbHits`，新版精确 Node ID Query 为 `6 dbHits`；工作量属于不同执行路径，不能直接解释为同一语句加速比或归因生产 OOM。
- 1k/10k/100k Node：精确 Node ID Seek 保持 `6 dbHits`，无关数据增加不放大 Seek 工作量；未建属性索引的谓词过滤仍可能线性扫描。
- Linux amd64 QEMU、1 GiB/no-swap 合成图，100k Node 未 Checkpoint / Checkpoint 后 `memory.peak` 分别为 `346,009,600` / `208,941,056` bytes；`oom_kill=0`，取消、重启、身份及 SQLite 完整性回验通过。
- 本地 `cargo make quality` 和 `scripts/ci.sh` 退出码 0；覆盖率 regions `84.93%`、functions `86.56%`、lines `88.13%`。真实 SQLite 3.45.0 / 3.53.4、Cypher TCK、Graph View、历史、写入/回滚、Provider/SQL 和 VM 回归由 [Phase 21 验收记录](../development/phases/21-predicate-routing-identity-seek.md) 维护。上述为本地证据，不替代本 Tag CI 或最终下载资产回验。

## 兼容、安全与限制

- `CY25-2026.08` 语言兼容范围不变；现有 `lithograph()` / `lithograph_rows()`、`EmbeddingProviderV1` 不变。标准 SQLite loadable extension，SQLite 3.45.0+，fresh/current storage format 3，无数据迁移要求。
- `libsqlite3-sys` bundled SQLite 相关 `RUSTSEC-2026-0459` 已按宿主 SQLite 动态链接的实际 feature graph 配置限定例外与到期复核检查；**例外不是对不可信宿主 SQLite 的安全保证**。
- 无 Checkpoint 的深历史 Snapshot overlay 解析以及缺少属性索引的查询仍有成本；更完整的 Planner/Executor、Tiered Checkpoint、Join 优化属于后续 [Phase 22](../development/phases/22-high-performance-query-optimizer.md)。本版本不宣称已根除 KG OS 生产 OOM 的全部成因。

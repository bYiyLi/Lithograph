# Lithograph v0.3.1

v0.3.1 提供完整中文开发者手册和 query-local 安全执行选项，并修复可执行手册验证发现的查询正确性问题。应用继续通过标准 SQLite SQL 调用，语言 Profile 为 `CY25-2026.08`，storage format 为 3，Embedding Provider SPI 为 V1。

## 完整开发者手册

- [产品手册](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/guide/README.md)：安装、接入、stream/transaction、Graph View、安全执行、搜索导入、版本与运维。
- [Cypher 25 使用手册](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/cypher/index.md)：完整语法、类型/表达式、路径、查询组合、修改、Schema/Index、搜索、batch 与函数。
- [接口参考](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/reference/README.md)：SQL/options/JSON、事务生命周期、Procedure、版本对象、Provider 配置与 SPI。

原有公开路径与章节入口保留。函数和 Procedure 结构化清单由目标版本扩展核对，正文例子从 Markdown 提取，经真实 SQL surface 检查 columns/rows 或具体错误；文档覆盖与链接检查进入 CI。用户正常使用所需说明在手册内完整提供。

## 安全执行选项

`lithograph()` 与 `lithograph_rows()` 的第三个参数可设置 `{"readOnlyNoExternalIO":true}`，active Lithograph explicit transaction 内同样可用。默认 false，非 Boolean（含 null）返回 `INVALID_ARGUMENT`。

完整 AST 在 prepare 阶段检查，覆盖嵌套子查询、条件分支、字符串插值、参数及零输入；EXPLAIN/PROFILE 不豁免。Graph/Schema/Index/Version/maintenance mutation、checkout、LOAD CSV、transaction subquery、Managed Semantic 和 Full-text Procedure 被拒绝。允许普通图/历史读取、SHOW、明确列出的 Version read 和 Raw Vector SEARCH。

该约束由宿主强制设置。它不限制其它直接 SQL，不替代 SQLite 宿主权限或 OS sandbox；完整允许集合及组合规则见 [Execution Options](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/reference/execution-options.md#read-only-no-external-io) 和 [安全指南](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/guide/safe-execution.md)。

## 正确性与依赖修复

- UUID 直接表达式的 `toString()` frontend 检查与已支持的 runtime 转换一致。
- 路径函数组合的类型检查按直接参数和属性 owner 判断，修复 `nodes()/relationships()` comprehension 与外层 `size()/type()` 的误判。
- 正确解析 regex `=~` 与双写字符串引号，Map projection 的显式 `key:expression` 不再被 RHS Property selector 覆盖。
- COLLECT 等表达式子查询的内层 alias、DISTINCT、ORDER BY、SKIP/LIMIT 不再污染外层投影。
- `count(DISTINCT *)` 不再被当作普通 count 静默执行；合法的 `count(*)` 和 `count(DISTINCT expression)` 保留。
- INTEGER64 Vector 构造保留整数精度，覆盖 64 位边界和超出浮点精确整数范围的坐标；超范围 Integer String 不再经浮点舍入成为合法边界值。
- Full-text 单个 prohibited term 正确保留其模式，纯负查询不会错误返回包含该词的文档。
- KEY/UNIQUE/Graph Type 验证复用清空的 connection-local TEMP scratch，修复 rows 活跃 statement 下删除 TEMP 表导致的 BUSY。
- Full-text analyzer 验证直接构造/释放实际连接的 tokenizer，避免 rows 下 DROP probe 的 Schema 锁，并以原生 SQLite DDL 差分验证 specification grammar，包括相邻 quoted/bare token。
- Native tokenizer 返回 `SQLITE_NOMEM` 时，scalar/rows 都保留 SQLite 的 canonical `out of memory` 错误与 primary code，并验证失败未发布 Schema。
- rustls 更新至 0.23.46，满足本次供应链检查的安全公告要求。

## 升级与已知限制

从 v0.3.0 升级保持公开 SQL surface、Profile 与存储兼容。读取 formats 1–3，新建和迁移目标为 3；v0.2.0/v0.2.1 的 format 4 仍不支持直接 downgrade/migration，应按旧版升级说明导出重建，不能手改 storage marker。

当前 `SHOW PROCEDURES` 参数/返回 metadata 的局限及 `SHOW INDEXES.createStatement` 的不完整导出，见 [Known Issues](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/reference/known-issues.md)。实际接口参数和类型由各项 Reference 完整说明。

## 下载与稳定引用

Release 包括 Linux/macOS/Windows x64/arm64 六个平台包与 `SHA256SUMS`。每包包含主 extension、独立 OpenAI-compatible Provider、README、LICENSE、COMMERCIAL-LICENSE 和 `VERSION=0.3.1`。

固定版本入口：[产品手册](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/guide/README.md)、[Cypher](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/cypher/index.md)、[Reference](https://github.com/bYiyLi/Lithograph/blob/v0.3.1/docs/reference/README.md)。运行要求为 SQLite 3.45.0+、loadable extension、FTS5 和线程安全支持。

## 发布后补充：可选 cache 的首次并发初始化

v0.3.1 OpenAI-compatible Provider 在多个进程首次同时初始化同一空 cache 时，可能让一个请求返回 `IO_ERROR`。启动并发 worker 前，应先由单个进程用目标配置完成一次有效请求。cache 默认禁用；已初始化 cache 的普通并发读写不涉及该首次创建窗口。详细证据、范围和规避见 [v0.3.1 已知问题补充](https://github.com/bYiyLi/Lithograph/blob/main/docs/reference/known-issues.md#provider-cache-first-use)。

本条是已发布 binary 的限制说明，产品修复尚未发布。已发布的 tag 与六个平台包保持原内容；发布后的补充信息以本 Release 页面和链接的 Known Issues 为准。

# Lithograph v0.3.7

v0.3.7修复磁盘容量耗尽时的错误报告与事务恢复。写入触发`SQLITE_FULL` (13)且SQLite已经自动回滚整个事务时，Lithograph保留`RESOURCE_ERROR`与原始SQLite code，避免重复清理已不存在的SAVEPOINT将容量错误覆盖为`INTERNAL_ERROR`。

## 修复行为

- 普通scalar、rows、Lithograph显式事务与最终`lithograph_tx_commit()`均保留明确的容量错误，不发布失败写入的部分Node或canonical history。
- 自动回滚后清除active/staged/cursor状态；恢复容量后，健康连接无需重新打开即可继续写入。Lithograph显式事务需要重新begin。
- caller-owned SQLite `BEGIN`可能已经整体回滚，包括宿主此前尚未提交的业务表写入；宿主应检查实际transaction状态及已提交状态，不自动重放写入。
- 自动checkpoint遇到已撤销外层canonical write的FULL时传播失败，避免把整个事务失败当成可延后的derived maintenance。
- 真正的清理失败继续执行原有完整回滚和连接隔离；本次修复不放宽NOMEM、interrupt或未知事务终态的处理。

## 验证范围

新增真实SQLite pager配额回归，覆盖DELETE/WAL两种日志模式下的普通scalar、显式事务内scalar、rows、caller-owned `BEGIN`和实际`tx_commit`五类边界。每类在同一连接执行三次故障/恢复，并使用完全相同的输入做解除配额成功对照；检查SQLite code、错误类别、无部分提交、显式状态清理、integrity和重开后的持久状态。

这是主库页数配额验证，不代替物理介质损坏、任意I/O故障或未知提交结果的验收。实现回归、主分支完整CI、Tag完整CI、六平台实际load与正式下载资产回验的实际结果分别记录在[补丁交付记录](https://github.com/bYiyLi/Lithograph/blob/main/docs/development/phases/22-high-performance-query-optimizer.md#v037-full-recovery)。

## 兼容与升级

标准SQLite loadable extension、公开SQL、`CY25-2026.08`、storage format **3**、既有Commit identity和Provider SPI V1保持兼容。没有新增外部依赖或数据库migration；已有format 3数据库可直接使用本补丁。v0.3.6交付的Phase 22优化继续保留，详见[v0.3.6发布说明](https://github.com/bYiyLi/Lithograph/blob/v0.3.6/docs/releases/v0.3.6.md)。

宿主SQLite要求与备份/升级边界见[安装指南](https://github.com/bYiyLi/Lithograph/blob/v0.3.7/docs/guide/installation.md)和[部署与维护](https://github.com/bYiyLi/Lithograph/blob/v0.3.7/docs/guide/operations.md)。不对容量恢复后的写入增加自动重试。

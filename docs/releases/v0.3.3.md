# Lithograph v0.3.3

v0.3.3 修复静态名称的反引号语义，将取消检查传播到长表达式，并增加宿主显式启用的 execution 内存预算。保持标准 SQLite loadable extension、`CY25-2026.08`、storage format **3**、既有 Commit identity 与 `EmbeddingProviderV1`。

## 查询正确性

静态 Node Label、Relationship Type 与 Label predicate 在进入执行结构时统一解码一次：去掉外围反引号，将双反引号还原为名称中的单个反引号。CREATE、MATCH、WHERE、Schema/Index、scan/seek、路径、历史 Snapshot 与 Graph View 对同一个实际名称使用一致语义。动态 Label/Type 已是实际字符串，不重复解码；AST 原文和位置保留。

修复合法反引号名称导致已存在人物查询返回空结果的问题；中文名称不需要额外替换或适配层。

## 长表达式取消

SQLite 的 `sqlite3_interrupt()` 现在传播到 `range()`、列表推导/谓词、嵌套 `reduce()` / `allReduce()`、集合与长值处理。表达式循环每至多 **256 work units** 检查，可分块文本每至多 **64 KiB** 检查；大规模分配、复制及不可拆分第三方调用前后另行检查。第三方单次调用进行中仍不保证异步抢占；不新增 query timeout option。

取消继续返回 `INTERRUPTED` / `SQLITE_INTERRUPT` (9)，不产生成功 summary。未发布写入回滚，active explicit transaction 整体 abort，transaction subquery 已 durable 的 batch 保留。取消 caller-owned SQLite transaction 中的 mutating execution 可能使整个 SQLite transaction 回滚，包括宿主此前尚未提交的业务写入。finalize/close 后检查实际 transaction 状态；无法确认清理成功的 connection 被 quarantine，应关闭丢弃。详见 [取消与连接池](https://github.com/bYiyLi/Lithograph/blob/v0.3.3/docs/reference/transactions.md#cancellation)。

## 显式执行内存预算

在 `lithograph(query, params, options)`、`lithograph_rows(query, params, options)` 或 explicit transaction 内的每次 execution options 中传入：

```json
{"readOnlyNoExternalIO":true,"memoryLimitBytes":67108864}
```

该例为 **64 MiB**，由宿主选择，不是默认配额。`memoryLimitBytes` 接受 `1..9223372036854775807` 的 JSON 整数；省略不新增限制。null、零、负数、小数、Boolean、字符串和越界值返回 `INVALID_ARGUMENT`。合法预算耗尽返回 `RESOURCE_ERROR` / `SQLITE_TOOBIG` (18)，不伪装成系统实际 OOM。

参数解码、Cypher Value、表达式中间值、行/batch、排序/聚合/去重工作缓冲、结果编码与 scalar collector 按存活容量计账；分配/扩容前预留，释放后归还。嵌套查询、分支和 concurrent batch 共享一次 execution 的预算，不同 execution 独立；begin 不设置或继承 execution 预算。`range()` 保留 200 万元素限制，并在分配前核对所需容量。

只返回一个数字也可能需要大中间值。例如 `RETURN size(range(1,500000)) AS c` 在 16 MiB 下被拒绝，256 MiB 下返回 `500000`。限制返回行数或只读均不能替代计算内存预算；大结果优先逐行消费，并检查最终 summary 和 SQLite 返回码。接入示例见 [应用集成](https://github.com/bYiyLi/Lithograph/blob/v0.3.3/docs/guide/integration.md#execution-memory-budget)，完整合同见 [Execution Options](https://github.com/bYiyLi/Lithograph/blob/v0.3.3/docs/reference/execution-options.md#memory-limit)。

**预算是受控执行工作内存的引擎计账上限，不是查询或进程 RSS 硬上限。** 它不覆盖宿主已有输入缓冲、Frontend AST/plan、SQLite 页缓存、Provider 内部内存及 allocator 隐含开销。现有 transaction inner batch 仍先形成完整 RowSet，再 durable commit 和输出 spill；预算可拒绝无法容纳的当前 batch，已 durable 的 earlier batch 保留，省略预算时该工作集仍可能增长。本版本不宣称 batch 内 provisional rows 已自动 spill，也不引入独立查询进程。

## 兼容与升级

- 省略新选项保持既有行为；`readOnlyNoExternalIO`、`readAccess` / `writeAccess` 组合及原有 type/null/error semantics 保持。
- v0.3.2 及更早发行库不接受 `memoryLimitBytes`；宿主升级二进制后仍须显式传入，才能启用预算。
- 从 v0.3.2 升级不要求新的图存储迁移。继续读取 formats 1–3，新建/迁移目标为 3；历史 format 4 不支持直接迁移或降级，不能手改 marker。
- 运行要求为 SQLite 3.45.0+、loadable extension、FTS5 与线程安全支持。Provider SPI V1、Provider cache schema/key 与既有 Commit ID 不变。
- Procedure metadata 与 `SHOW INDEXES.createStatement` 完整性限制仍保留，见 [Known Issues](https://github.com/bYiyLi/Lithograph/blob/v0.3.3/docs/reference/known-issues.md)。

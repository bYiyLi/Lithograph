# Lithograph v0.2.1

Lithograph v0.2.1 发布 Phase 14 SQL Explicit Transaction Adapter。普通 SQLite driver 可以在同一 connection 上通过 SQL function 执行 `begin -> execute* -> commit | abort`，无需自行绑定 `lithograph_v1_tx_*` C API。

Native ABI 仍为 1，Embedding Provider ABI 仍为 V1，Cypher profile 仍为 `CY25-2026.08`，storage format 仍为 4。

## SQL Explicit Transaction

新增四个 direct-only SQL scalar：

- `lithograph_tx_begin(options_json)`；
- `lithograph_tx_execute(query [, params_json [, options_json]])`；
- `lithograph_tx_commit()`；
- `lithograph_tx_abort()`。

最小用法：

```sql
SELECT lithograph_tx_begin('{"author":"app","message":"create two people"}');
SELECT lithograph_tx_execute('CREATE (:Person {name: ''张三''}) FINISH');
SELECT lithograph_tx_execute('CREATE (:Person {name: ''李四''}) FINISH');
SELECT lithograph_tx_commit();
```

`tx_begin` 内部执行 `BEGIN IMMEDIATE`；后续 `tx_execute` 可见同一 transaction 先前的 staged changes；`tx_commit` 只生成一个最终 graph Commit 并提交 SQLite transaction。只读 transaction 不新增 Commit；发生过 mutation 但最终净变化为空时，仍沿用 empty-delta Commit 规则。

任一 `tx_execute` 参数、prepare、execution、callback、取消或结果构造失败都会 fail-closed rollback 整个 explicit transaction。调用方不在外层再执行 `BEGIN` / `COMMIT`；已有 caller-owned SQLite transaction 时 `tx_begin` 按原合同拒绝。

完整参数、结果、错误与连接池边界见 [SQL API Reference](../reference/sql-api.md) 与 [事务指南](../guide/transactions.md)。

## 从 v0.2.0 升级

v0.2.1 不改变 storage format，从 v0.2.0 升级只需替换与宿主 OS/CPU 匹配的 Lithograph 与 OpenAI-compatible Provider extension 制品。仍建议在替换前备份数据库，并在真实宿主 SQLite/connection pool 中执行代表性读写、Semantic 与 explicit transaction smoke。

从 v0.1.1 或更早版本跨版本升级时，仍需按 [v0.2.0 Release Notes](v0.2.0.md) 执行 format 3 → 4 migration 与 Provider 部署检查。

## Runtime 与兼容性

- 最低 SQLite：3.45.0，必须支持 loadable extension 与 FTS5。
- Release gate 同时验证 SQLite 3.53.4。
- Native ABI：1，未改变。
- Embedding Provider ABI：V1，未改变。
- Cypher profile：`CY25-2026.08`，未改变。
- storage format：读取 1–4，新建与迁移目标为 4。
- 普通 `lithograph()`、caller-owned SQLite transaction、Raw Vector / `SEARCH`、Full-text 与 Managed Semantic 合同不变。

## 已知边界

- Explicit transaction 会持有 SQLite single-writer ownership，应保持短小；不在其中等待用户输入、长时间网络 I/O 或其它无界外部工作。
- `tx_execute` 不接受 Version Procedures、`LOAD CSV`、transaction-owning Cypher 或 branch/metadata override；这些入口需要自己的 transaction boundary。
- `lithograph.branch.checkout`、Native `NULL,0` JSON 默认值与 Procedure introspection metadata 的既有问题未在本版本修复；见 [Known Issues](../reference/known-issues.md)。
- 本版本仍是 pre-1.0 release；升级生产数据库前必须使用真实宿主 SQLite、连接池与恢复流程完成演练。

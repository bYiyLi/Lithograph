# Lithograph v0.3.6

v0.3.6 交付 **Phase 22：高性能查询优化器与可预算执行引擎**。复杂 MATCH、Join 和循环模式可按实际访问条件、基数、成本与预算选择执行路径，减少无关扫描和重复中间结果；深历史读取与维护使用可重建的 checkpoint/统计数据。既有 SQL 执行接口、Cypher Profile、存储格式和版本历史合同保持兼容。

## 查询与历史性能

- 统一有界 Planner 与 query-scoped Executor 资源账目，覆盖读写、SQL scalar/rows、historical/staged 和多 MATCH 组合；缺少类型、索引或成本证明时沿用正确回退。
- 自动 Tiered Checkpoint、兼容祖先增量构建和 Snapshot 复用，减少深历史反复从 Root 重放；checkpoint 与 statistics 保持可删除、可重建的 derived data。
- Versioned Statistics、Relationship Element ID Seek、安全 Predicate/Scan，以及 DPhyp/Greedy Join Order、Index Nested Loop 与有界 Hash/Grace Spill。
- Semi-mask/SIP、Join Dynamic Filter、TopK、Factorized intermediate 与 Accumulate–Semijoin–Probe，减少无效读取和重复复制，保留逐行 multiplicity、NULL/错误及写入副作用。
- 安全循环子组件可选择 WCOJ/Multiway Intersection，使用真实有序邻接访问；parallel Relationships、自环、方向/Type 和 per-MATCH Relationship uniqueness 保持正确。

这些优化由成本与可证明的适用边界决定，不承诺每种查询都选择新算法或获得相同比例的加速。没有属性索引的真实 Scan 仍有候选域扫描成本。

## 正确性与资源修复

- 修复 HNSW 同分邻接剪枝可能造成 base graph 断连、ready 查询反复失效重建的问题；在原 `2*M` base-layer 邻居上限内保留导航环，保持 score、cutoff tie、Graph View 和既有 recall 合同。
- 修复跨算法组合中的 PROFILE slot/行计数、规划预算分配和 Grace workspace 保留问题，覆盖 early-close、interrupt、RESOURCE_ERROR、回滚与重启恢复。
- 普通查询、SQLite explicit transaction 与 `CALL … IN TRANSACTIONS` 分别保留各自发布/回滚边界，不撤销已合法 durable 的 inner batch。

## 验收范围

Phase 22 的八个 Stage、46 项局部和6项全局验收已完成，完整结果和原失败见[最终验收记录](../development/phases/22-high-performance-query-optimizer.md#phase22-final-acceptance)：

- 原生 Linux x86_64、1 GiB/no-swap；四档增长、百万完整输出、小预算与故障/取消恢复。
- 1/4/8 readers + writer，每档5分钟，合计15分钟；10M Nodes / 100M Relationships 的原规模门槛与 NR13 的10K冲突、40轮Merge全部指标通过。
- 独立1M×128、100K×1536 FLOAT32与1M全文corpus，Core与普通SQL双入口完整Oracle；主测及条件复测中当前版共3200条ordinary ready，向量recall@10均1.0。

上述性能证据来自Phase开发验收构建，算法源码与本次版本准备相同；版本元数据更新后的正式制品另由本Tag CI与六平台Release Matrix验证。Search分位数限各query单连接100次ready；首次完整构建单独记录，向量fixture只有两个非零坐标，不扩大为任意高熵embedding的延迟承诺。保留原始慢值、受控停止及历史Windows Provider单次BUSY根因未确定的记录。

## 兼容与升级

- 标准SQLite loadable extension；`lithograph()`、`lithograph_rows()`、SQL explicit transaction和`EmbeddingProviderV1`保持原接口。
- `CY25-2026.08`、fresh/current storage format **3**及既有Commit identity不变。已有format 3数据库不需要导出重建来使用本次查询优化；旧格式升级边界见[部署与维护](../guide/operations.md)。
- `memoryLimitBytes`、`readOnlyNoExternalIO`、`readAccess`/`writeAccess`及Graph View语义保持。没有增加公开Cypher hint、隐藏兼容模式或独立服务。
- SQLite **3.45.0+**为API/ABI兼容基线；宿主SQLite的安全版本要求与不可信数据库/WAL边界见[SQLite Baseline](../design/runtime.md#sqlite-baseline)。发行包使用宿主SQLite API，不随扩展嵌入私有SQLite副本。
